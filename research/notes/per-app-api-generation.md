# Engineering an API on the fly for consumer apps with no public API (state as of 2026-11-14)

Scope: five techniques for turning a consumer app into an MCP server / tool map, how well each works today, live probes against the real target apps, the legal and ToS picture, and a per-app difficulty rating for Canvas LMS (students), gym apps (Strong, Hevy, Fitbod, Apple Fitness) and nutrition apps (MyFitnessPal, Cronometer, MacroFactor, Lose It).

Live tests were run from a Mac on 2026-11-14 (US West, residential IP, plain curl with a Chrome user agent, plus FastMCP pulled fresh via uvx). They are marked "(live probe)". Nothing was logged into; no credentials were used.

## 1. Technique 1: official/public APIs and existing community MCP servers

### Takeaway
Of the nine targets, only Canvas (REST + personal access tokens) and Hevy (Pro-only API key) have a public, user-reachable API with write support, and both already have many community MCP servers. Every nutrition app either has no API (Cronometer, MacroFactor), a closed one (MyFitnessPal: "not accepting requests"), or a business-only read-only beta (Lose It); yet unofficial MCP servers built on reverse-engineered endpoints already exist for MyFitnessPal, Cronometer and Lose It, and the ecosystem moved fast in 2026.

### Inferences
- Official APIs give you the cleanest read+write for exactly two of nine targets (Canvas when the school allows student PATs, Hevy for Pro users). For the rest, "Technique 1" is really "find the community MCP that someone already reverse-engineered", which is fast to adopt but inherits all of Technique 3's fragility and ToS risk.
- The Canvas PAT path is quietly closing at the institution level (Sept 2025 setting, big schools banning students in 2025-2026). A product cannot assume a student can mint a token; it needs a fallback (browser session on the web app) for locked-down schools.
- Platform API owners (Strava, Google Health restricted scopes, MFP closed program) are moving toward gating AI use specifically, so "official API" does not mean "allowed for an AI agent".

### Gaps
- Exact fraction of Canvas institutions that block student PATs: no dataset found.
- No primary Hevy or Strong documentation on Apple Health write scope beyond a vendor summary (Hevy writes workout type, duration, energy; set/rep detail stays in-app). [Sahha Hevy page](https://sahha.ai/integrations/hevy/)
- Whether ChatGPT Health's MyFitnessPal connector supports writes (logging meals) is reported inconsistently; OpenAI's own material frames it as nutrition advice.
- Smithery and the official MCP Registry were not crawled exhaustively; listings above come from Glama, LobeHub, mcpservers.org and PyPI.

## 2. Technique 2: auto-generated MCP from specs (OpenAPI to MCP) and API discovery

### Takeaway
Spec-to-MCP generation is mature (Stainless, Speakeasy, FastMCP, others) but only applies where a spec exists, which among the targets is just Hevy and Canvas. Live testing showed the real-world friction: FastMCP rejected Hevy's real spec until four schema defects were patched, and Canvas's spec is legacy Swagger 1.2 with 1,139 operations, far too many to expose raw as tools.

### Cited Findings
- Speakeasy generates standalone MCP server repos from OpenAPI 3.0/3.1 (`speakeasy quickstart --mcp`), can emit MCPB bundles or Cloudflare configs; Stainless generates MCP servers (`stainless mcp generate --openapi`), docs call it experimental and say it "may not handle all types of OpenAPI spec yet". [Speakeasy: Standalone MCP](https://www.speakeasy.com/docs/standalone-mcp); [Stainless: Generate an MCP server](https://www.stainless.com/docs/guides/generate-an-mcp-server); [Speakeasy: comparison of MCP generators](https://www.speakeasy.com/blog/comparison-mcp-server-generators); [Stainless: lessons converting complex OpenAPI specs](https://www.stainless.com/blog/what-we-learned-converting-complex-openapi-specs-to-mcp-servers)
- (live probe) FastMCP `FastMCP.from_openapi()` (latest from PyPI via uvx on 2026-11-14) failed on Hevy's published spec with `ValueError: Invalid OpenAPI schema` caused by non-standard `type: "enum"` on three schemas (CustomExerciseType, MuscleGroup, EquipmentCategory) and a boolean `required: true` on a property. A 15-line normalizer (enum to string, drop boolean required) fixed it, after which FastMCP generated 22 tools, one per operation, with names derived from summaries and truncated (e.g., `Get_a_paginated_list_of_exercise_templates_available_on_`). Because the spec defines no `securitySchemes`, the `api-key` header surfaced as a tool argument on every tool, meaning the LLM would be asked to supply the secret unless the wrapper injects it. FastMCP also warned that passing an `httpx.AsyncClient` is deprecated. [Hevy Public API Docs (spec source)](https://api.hevyapp.com/docs/)
- (live probe) Canvas publishes its API as Swagger 1.2 JSON: 148 resource files under `/doc/api/*.json`, totaling 1,139 operations (574 GET, 241 POST, 190 PUT, 128 DELETE, 6 PATCH). [Canvas api-docs.json index](https://canvas.instructure.com/doc/api/api-docs.json)
- Existing Canvas MCP servers already curate rather than mirror the spec, e.g., role-filtered tool sets and student-only read-only servers. [Glama bruchris/canvas-lms-mcp](https://glama.ai/mcp/servers/bruchris/canvas-lms-mcp); [mcpservers.org Canvas](https://mcpservers.org/servers/kdude43ver/canvas-api-mcp)
- Discovery: Instructure documents REST, GraphQL and LTI 1.3 publicly (per ibl.ai's October 2026 survey). [ibl.ai](https://ibl.ai/developer/connectors/canvas)

### Inferences
- For an "engineer its own API" system, Technique 2 is a step inside the pipeline, not a route on its own: after Technique 3 recovers endpoints, the system should emit an OpenAPI 3.1 document, run a validator/normalizer (LLMs are good at fixing defects like Hevy's), then generate tools. The Hevy result shows even first-party specs need this repair pass.
- Tool-count control matters more than generation: 1,139 Canvas operations would blow any model's tool budget. A student tool map probably needs ~15 to 30 curated operations (courses, assignments, submissions, grades, calendar, announcements, discussions, files, modules, to-dos).
- Auth must be lifted out of tool arguments into the transport (header injection), which off-the-shelf generators do not do automatically when the spec omits `securitySchemes`.
- Swagger 1.2 is not accepted by OpenAPI 3.x-only generators without a conversion step (based on FastMCP's strict 3.x parser behavior observed on Hevy; not separately tested on Canvas).

### Gaps
- Did not run Stainless or Speakeasy against Hevy or Canvas (both require accounts/CLI login); their tolerance for Hevy's defects is untested.
- No authoritative survey found on how agents discover APIs at runtime (e.g., well-known OpenAPI locations, llms.txt, MCP registry lookups) beyond vendor posts.

## 3. Technique 3: network-traffic reverse engineering (HAR, mitmproxy, Frida) plus LLM client generation

### Takeaway
This is the technique that actually produced working read+write tools for MyFitnessPal and Cronometer in 2026, and open-source tooling (Integuru, reverse-api-engineer, Unbrowse) now automates HAR-to-client generation. For web-backed apps a one-time desktop browser capture is enough; for mobile-only apps (Strong, Fitbod, MacroFactor) the work requires APK static analysis plus Frida/mitmproxy on a desktop with a rooted/emulated Android device, and attestation or TLS fingerprinting can block replay from servers.

### Cited Findings
**Tools and projects**
- Integuru (AGPL-3.0, ~4.8k stars): you record a HAR + cookies while doing an action in a browser, give a prompt ("download utility bills"); the agent finds the target request, identifies dynamic parameters, walks back to the requests that produce them to build a dependency graph until only auth cookies remain, then generates runnable Python. Uses OpenAI models (gpt-4o for graph, o1-class for codegen). For 2FA sites you complete 2FA yourself and capture the resulting tokens. The open repo is "v0"; the company now sells a hosted version. [GitHub Integuru-AI/Integuru](https://github.com/Integuru-AI/Integuru)
- reverse-api-engineer (kalil0321, MIT): CLI that records Playwright traffic as HAR and has an LLM generate a typed `api_client.py`, usage example and endpoint README; ships as a Claude skill with `har_filter.py`/`har_analyze.py`; notes sites with aggressive bot detection may block capture. Versions reported 0.10.0 (PyPI) to 0.14.0 (GitHub). [PyPI reverse-api-engineer](https://pypi.org/project/reverse-api-engineer/); [DEV: Reverse engineering undocumented APIs with Claude](https://dev.to/kalil0321/reverse-engineering-undocumented-apis-with-claude-1l33); [everydev summary](https://www.everydev.ai/tools/reverse-api-engineer)
- Vercel's agent-browser ships a `derive-client` skill in the same vein. [tessl registry: derive-client](https://tessl.io/registry/skills/github/vercel-labs/agent-browser/derive-client)
- Unbrowse ("Internal APIs Are All You Need", arXiv 2604.00694, Apr 1, 2026; Tham, Garcia, Hahn): passively learns "shadow API" routes from real browsing traffic, pools them in a shared route graph, executes local cache > shared graph > browser fallback; across 94 domains, warmed cached execution averaged ~950 ms vs ~3,404 ms for Playwright (3.6x mean, 5.4x median speedup), well-cached routes under 100 ms; proposes x402 micropayments for route lookups; exposed via CLI, MCP and AgentSkills. Abstract does not address auth or ToS. [arXiv 2604.00694](https://arxiv.org/abs/2604.00694); [mcpmarket: Unbrowse](https://mcpmarket.com/server/unbrowse)
- Third-party analyses flag that reverse-engineered integrations have no stability guarantees and may raise ToS/CFAA issues; Integuru's "99.9%+ success" appears only in its own marketing. [dev.co on Integuru](https://dev.co/ai/frameworks/integuru); [brightcoding blog](https://blog.brightcoding.dev/2025/08/12/integuru-the-ai-agent-that-lets-you-automate-any-web-workflow-no-public-api-required)

**Worked mobile example (Cronometer)**
- The Cronometer mobile API was reverse-engineered via (1) static analysis of `libapp.so` (Dart AOT snapshot) from the APK to find endpoint names, (2) traffic interception via Frida + mitmproxy to capture exact formats, (3) trial and error against the live API. It uses `POST /api/v2/*` with JSON-body auth for most operations and `DELETE /api/v3/user/{id}/*` with an `x-crono-session` header for deletions; login answers `TOTP_CODE_REQUIRED` when 2FA is on. [PyPI cronometer-api-mcp](https://pypi.org/project/cronometer-api-mcp)

**Worked web example (MyFitnessPal)**
- MFP sits behind Cloudflare + NextAuth; the working approach reuses the browser session cookie and impersonates Chrome's TLS fingerprint with curl_cffi; troubleshooting advice is to try different impersonation targets and notes datacenter IPs get challenged more often. [PyPI mfp-mcp](https://pypi.org/project/mfp-mcp/); [Socket.dev mfp-mcp](https://socket.dev/pypi/package/mfp-mcp)
- (live probe) `www.myfitnesspal.com/account/login` returned 200 via Cloudflare (`server: cloudflare`, `cf-ray`) to plain curl; an unauthenticated `.../api/services/diary` returned a 400 JSON error, i.e., no challenge page for a single residential request. `www.fitbod.me` returned `403` with `cf-mitigated: challenge` to the same plain curl. `loseit.com` and `strong.app` are also Cloudflare-fronted; `cronometer.com` showed no Cloudflare headers. [myfitnesspal.com](https://www.myfitnesspal.com/account/login); [fitbod.me](https://www.fitbod.me/)

**Mobile obstacles**
- Certificate pinning is routinely bypassed with Frida runtime hooks (CodeShare scripts, Objection automation) without repackaging, on a rooted/instrumented device; pinning alone does not stop a determined user. [Approov: bypass pinning with Frida](https://blog.approov.io/how-to-bypass-certificate-pinning-with-frida-on-an-android-app); [StingrAI, May 2026](https://www.stingrai.io/blog/your-app-is-pinned-we-got-in-ssl-pinning-bypass); [ProAndroidDev](https://proandroiddev.com/why-certificate-pinning-alone-wont-stop-modern-mitm-attacks-469e1d182bea)
- Play Integrity: a March 2026 SANS paper found the stricter device-integrity verdict blocked every spoofing tool tested (7 attempts); adoption of Play Integrity is uneven across apps per an ODU paper. [SANS white paper](https://www.sans.org/white-papers/can-root-detection-be-trusted-bypass-techniques-mobile-platforms); [ODU paper (Apr 2026)](https://vsgc.odu.edu/wp-content/uploads/2026/04/MacDonald_Collin_Paper.pdf); [Root detection is dead (2026)](https://levelup.gitconnected.com/root-detection-is-dead-what-actually-works-in-android-2026-b7f801e50531)
- On-device capture on iPhone is possible with Proxyman for iOS, which runs a local VPN forwarding to an on-device MITM server with a user-generated root certificate (iOS 17+). [App Store: Proxyman](https://apps.apple.com/app/proxyman/id1551292695)

### Inferences
- Phone vs server split: (a) Discovery for web-backed services (MFP, Cronometer web, Lose It web, Canvas, Hevy web) needs only a one-time desktop or cloud-browser session to record a HAR; no phone work. (b) Discovery for mobile-only apps (Strong, Fitbod, MacroFactor) needs a desktop with an Android emulator or rooted device and Frida if the app pins; iOS on-device MITM (Proxyman-style) only works for apps that do not pin, and Frida on stock iOS requires re-signing the IPA from a Mac. A consumer cannot do (b) from their phone alone. (c) Execution of the resulting client can run on a server only where the backend accepts replayed tokens from a datacenter IP; MFP's Cloudflare TLS fingerprinting and datacenter challenges argue for executing from the user's device or a residential egress.
- Discovery is a one-time cost per app that can be shared across all users (Unbrowse's shared route graph idea), but credentials and tokens are per-user and must stay with the user.
- Token refresh is the long-tail failure: MFP cookies reportedly expire around 30 days (per a listing) and mfp-mcp needed a headless-browser refresher; Cronometer needs TOTP handling. Any product must budget for re-auth UX.
- Attestation (Play Integrity, App Attest) is the true wall: if a backend demands a valid attestation token per request, a server-side client cannot mint one. None of the target apps was confirmed to enforce this; the fact that community clients for Cronometer's mobile API work suggests it does not (inference).
- The MFP history (2022 captcha, Cloudflare + NextAuth migration, client-side food form) shows breakage roughly yearly or faster; self-healing (re-capture on failure) is required, not optional.

### Gaps
- No primary source found on Apple App Attest bypass state in 2026; Approov limitation post was title-only.
- Did not verify whether Strong, Fitbod or MacroFactor pin certificates or use Play Integrity/App Attest (would need APK analysis; not attempted).
- Kadoa, Firecrawl and Browserbase were named in the brief; no source found showing any of them offering network-level "API discovery" (Stagehand caches UI actions, not endpoints; see section 4).
- Integuru hosted product pricing and current capabilities not verified.

## 4. Technique 4: automating the web version with cloud browser agents

### Takeaway
Browser agents logging in as the user are the most general route for Canvas, MyFitnessPal, Cronometer, Lose It and Hevy web, but they cost cents to dollars per task and take minutes, versus milliseconds for a direct API call; MacroFactor, Strong and Fitbod have no usable web app, so this route is closed for them. Login and 2FA are handled by persisting browser contexts after a one-time human login, TOTP secrets, or human handoff.

### Cited Findings
- Browser Use Bench v2.1 (180 long tasks on live websites, Oct 17, 2026): Browser Use's own agent scores 72.9 at 11 cents/task, level with Claude Sonnet 5.5 high at 14x lower cost; top run GPT-6.1 Sol medium at 79.6 (vendor benchmark). An earlier V1 set had a Claude model at 80% for ~$5.80/task and ~6m53s average. [Browser Use benchmarks](https://browser-use.com/benchmarks); [Browser Use: AI browser agent benchmark](https://browser-use.com/posts/ai-browser-agent-benchmark)
- Asana reported an optimized browser agent at ~$0.47 model cost and ~4 minutes per run (single-customer vendor case). [aipricing.guru](https://www.aipricing.guru/news/asana-browser-agent-gpt-6-1-sol-cost-october-2026/)
- One cost comparison claims a ~45x cost gap between computer use and structured APIs (secondary blog, methodology unverified). [promptcost](https://promptcost.pages.dev/en/blog/computer-use-vs-structured-apis-cost-2026)
- Unbrowse measured ~3.4 s average per Playwright-automated retrieval vs ~0.95 s via cached internal API. [arXiv 2604.00694](https://arxiv.org/abs/2604.00694)
- OSWorld-Verified (369 desktop+web tasks): leaderboards in mid to late 2026 show top models around 85-86% and an agent system at ~90%; aggregators disagree, and provider-reported numbers may use different conditions. [BenchLM OSWorld-Verified](https://www.benchlm.ai/benchmarks/osworld-verified); [Yutori leaderboard](https://yutori.com/leaderboards/osworld-verified.md); [Developers Digest](https://www.developersdigest.tech/models/best-for/computer-use)
- Auth: Browserbase "contexts" persist cookies, tokens and local storage so you log in once and reuse state; a customer logged into a utility portal once to avoid repeated 2FA; a 1Password extension can fill logins without returning credentials to the app. [Browserbase docs: Authentication](https://docs.browserbase.com/guides/authentication); [Browserbase template: manual MFA with contexts](https://browserbase.com/templates/manual-mfa-with-contexts)
- Browser Use can generate TOTP codes from a stored secret; email/SMS 2FA rated medium difficulty. CloudCruise requires a 2FA code delivered within 5 minutes. [Browser Use: web agent authentication](https://browser-use.com/posts/web-agent-authentication); [CloudCruise 2FA docs](https://docs.cloudcruise.com/concepts/twofactor.md)
- Stagehand caches successful actions and replays them without LLM calls, self-heals by falling back to inference when a selector stops resolving; local `cacheDir` replay has no token cost. A Browserbase customer (Starlight) built a "discovery agent" that maps UI capabilities into file-system "skills" another agent uses. [Stagehand docs: caching](https://docs.stagehand.dev/best-practices/caching); [Browserbase blog: Stagehand caching](https://browserbase.com/blog/stagehand-caching); [Browserbase x Box](https://browserbase.com/blog/browserbase-box-agents-browser-and-file-system)
- (live probe) MacroFactor's `app.` subdomain is an app-store link page, not a web app; Fitbod's site is behind a Cloudflare managed challenge. [app.macrofactor.com](https://app.macrofactor.com/); [fitbod.me](https://www.fitbod.me/)

### Inferences
- Per-action cost: a logged-in browser agent doing "log 2 eggs and toast to breakfast" is plausibly $0.05 to $0.50 and 30 s to several minutes; the same action via a learned API is effectively free and sub-second. The economic answer is to use the browser agent for discovery and as a fallback, then compile to API calls (Unbrowse/Stagehand pattern).
- SSO is a specific Canvas problem: many schools front Canvas with Shibboleth/SAML plus Duo, so a cloud browser needs a human-in-the-loop first login and a persisted context; Duo push cannot be automated without the user's phone.
- Cloud browsers run from datacenter IPs, which Cloudflare-fronted apps (MFP, Lose It, Fitbod) challenge more, so residential egress or running the browser on the user's machine improves reliability (and, per the Perplexity ruling, the legal posture; see section 7).

### Gaps
- No public per-site success rates for MFP/Cronometer/Canvas/Lose It flows with any browser agent.
- OpenAI Operator/ChatGPT agent "takeover" behavior for logins was not documented in sources found.
- Browserbase pricing per session-minute not verified.

## 5. Technique 5: native-app UI automation and caching learned flows as reusable "APIs"

### Takeaway
Driving the native app through the accessibility tree or screenshots works on Android (AndroidWorld success rates reportedly 85 to 91% for top agents, self-reported) and is the only universal route for mobile-only apps like Strong, Fitbod and MacroFactor; on iOS, third-party UI automation is not possible from another app, so the practical iOS hooks are App Intents/Shortcuts. Research in 2025-2026 is converging on recording a demonstration once and compiling it into a parameterized tool, sometimes by sniffing the API calls underneath.

### Cited Findings
- AndroidWorld (116 tasks): original 2024 paper's best agent 30.6% vs 80% human; DroidRun self-reports 63% (June 2025, Gemini 2.5 Pro, accessibility-based) and later 91.4%; an AppCards study reports 88.8% with GPT-5 and attributes 84.5% to MobileUse. A small third-party test of 65 real-world tasks found DroidRun best at 43%. [AndroidWorld paper](https://arxiv.org/pdf/2405.14573); [DroidRun blog](https://droidrun-ai.pages.dev/blog/how-we-achieved-state-of-the-art-android-world-benchmark-results); [AppCards](https://lisalsj.github.io/Droidrun-appcard); [AIMultiple mobile agent test](https://research.aimultiple.com/mobile-ai-agent)
- Android AppFunctions (Android 16+): platform API + Jetpack library that lets apps expose functions to agents, described by Google as the on-device counterpart to MCP tools; Gemini integration in private preview with trusted testers as of May 2026; callers need EXECUTE_APP_FUNCTIONS. Google is also building a UI automation framework for apps without AppFunctions; Gemini's agentic ordering starts with curated US food delivery, grocery and rideshare apps. [Android Developers: AppFunctions](https://developer.android.com/ai/appfunctions?hl=en); [9to5Google, Feb 2026](https://9to5google.com/2026/02/25/android-appfunctions-gemini/); [Android Developers blog: The intelligent OS](https://developer.android.com/blog/posts/the-intelligent-os-making-ai-agents-more-helpful-for-android-apps?hl=pt-br)
- Apple: iOS 26.1 betas showed MCP support being built into App Intents (Sept 2025). WWDC 2026 confirmed MCP/ACP support in Xcode 27; claims that iOS 27 adopts MCP system-wide are single-source and unconfirmed. [9to5Mac: macOS 26.1 beta MCP](https://9to5mac.com/2025/09/22/macos-tahoe-26-1-beta-1-mcp-integration/); [AppleInsider](https://appleinsider.com/articles/25/09/22/ios-26-could-get-a-major-ai-boost-with-the-model-context-protocol); [FoneArena WWDC26](https://www.fonearena.com/blog/?p=484623); [SoftwareSeni (unverified iOS 27 claims)](https://www.softwareseni.com/why-apple-is-retiring-sirikit-and-what-app-intents-means-for-developers)
- MacroFactor writes can be driven through an Apple Shortcuts action (used by a community MCP Worker), showing App Intents as a sanctioned write path on iOS when the app exposes one. [Glama macrofactor listing](https://glama.ai/mcp/servers/NasserAlbusaidi/macrofactor-mcp)
- Learning reusable tools from demonstrations: GOAL "GUI-Observe-API-Learn" (Technical Disclosure Commons, May 2026) replays a demonstrated workflow in a sandbox while a sniffer agent captures the underlying API calls, then emits a parameterized skill chaining atomic tool calls. [TDCommons GOAL](https://www.tdcommons.org/dpubs_series/10260)
- Work2Skill (arXiv 2610.12984): 350 recorded desktop demonstrations, induces skills with workflow rules, dependencies and completion checks. [opentrain summary](https://www.opentrain.ai/papers/work2skill-capturing-human-gui-experience-for-reusable-agent-skill-induction--arxiv-2610.12984/)
- Alloy (arXiv 2510.10049) turns browser demonstrations into editable reusable workflows; ShowUI-Aloha builds a procedural template from one demo; AppAgent-Claw (arXiv 2606.05171) turns a recorded demo into a reusable GUI workflow with layered target localization and validation; Salesforce GPA records one demonstration into a variable-parameterized template exposed as an MCP or CLI tool. [Alloy](https://arxiv.org/html/2510.10049v1); [ShowUI-Aloha](https://api.emergentmind.com/papers/2601.07181); [AppAgent-Claw](https://arxiv.org/pdf/2606.05171); [Salesforce GPA](https://www.salesforce.com/blog/gpa-gui-process-automation/)

### Inferences
- The best-of-both design is GOAL-like: drive the UI once (human demo or agent), capture network calls underneath, and compile to a direct API tool; keep the UI script as the self-healing fallback when the API call starts failing.
- For iPhone users, a phone-only product cannot drive other apps' UIs; it can (a) call App Intents/Shortcuts actions apps expose, (b) read/write HealthKit via its own native app, (c) use a Mac/cloud Android emulator for UI automation. Android users can be served on-device via accessibility-service agents (DroidRun-style) today.
- Benchmark rates (85 to 91%) are on fixed emulator task suites; real-world rates on arbitrary third-party apps look much lower (43% in the one independent test), so UI automation alone is not reliable enough for unattended writes like logging food.

### Gaps
- Work2Skill and AppAgent-Claw details verified only through abstracts/aggregators.
- No evidence found on whether Strong, Fitbod, Hevy, MFP, Cronometer or Lose It expose App Intents/Shortcuts actions (MacroFactor appears to).
- Whether iOS 27 shipped system MCP for third-party apps is unconfirmed.

## 7. Legal and ToS risk (CFAA, Van Buren, hiQ, Amazon v. Perplexity, DMCA 1201) when automating your OWN account

### Takeaway
After Van Buren (2021), hiQ (2022) and especially the Ninth Circuit's Aug 4, 2026 Amazon v. Perplexity opinion, a user automating their own account with a tool that runs through their own device is unlikely to be a CFAA violator, and the tool vendor is not the "accessor" when it merely instructs a locally running agent. The live risks are contract/ToS (account bans, breach claims), a cease-and-desist that revokes permission (Power Ventures), server-side architectures that talk directly to the target, and DMCA 1201 exposure for distributing pinning/attestation bypass tools.

### Cited Findings
- Amazon v. Perplexity (N.D. Cal. 3:25-cv-09514): Judge Chesney granted a preliminary injunction on Mar 9-10, 2026, reasoning user permission is not the same as Amazon's authorization; Amazon alleged Comet did not identify itself as an AI agent and breached its terms. [Bloomberg, 2026-03-10](https://www.bloomberg.com/news/articles/2026-03-10/amazon-wins-court-order-blocking-perplexity-s-ai-shopping-bots); [The Fashion Law](https://www.thefashionlaw.com/court-blocks-perplexity-from-accessing-amazon-systems-in-agentic-ai-lawsuit/); [Cooley](https://www.cooley.com/news/insight/2026/2026-08-06-ninth-circuit-rules-on-ai-agent-access-to-third-party-websites-under-cfaa)
- Ninth Circuit, No. 26-1444, Aug 4, 2026: vacated and remanded. "Access" means entering the computer system; the CFAA's "whoever" refers to a person; "However advanced the Assistant currently is, it is a tool, not a person for statutory purposes." The user, not Perplexity, accessed Amazon. Factual basis: Comet captures screenshots locally, Perplexity's servers return navigation instructions, and "Perplexity itself does not directly communicate with Amazon's servers"; distinguished Power Ventures where the defendant's own systems contacted Facebook. Same result likely under California's CDAFA. Rule of lenity invoked because Amazon's theory could criminalize end users of agents. [Ninth Circuit opinion PDF](https://www.courthousenews.com/wp-content/uploads/2026/08/amazon-v-perplexity-ninth-circuit-opinion.pdf); [Eric Goldman blog](https://blog.ericgoldman.org/archives/2026/08/ninth-circuit-lifts-restrictions-on-agentic-ai-accessing-amazon.htm); [Cooley](https://www.cooley.com/news/insight/2026/2026-08-06-ninth-circuit-rules-on-ai-agent-access-to-third-party-websites-under-cfaa)
- Limits: "We do not establish a new legal regime governing agentic AI"; preliminary record only; did not decide whether more Perplexity control would make it the accessor, whether access was unauthorized, or the $5,000 loss element; a footnote says the ruling "does not impair Amazon's ability to regulate access to Amazon.com via private terms of service". Cooley notes agents that do not use the user's machine as relay (direct server-to-server) pose greater risk. Amazon said it disagreed and was weighing options (rehearing/cert). [Goldman](https://blog.ericgoldman.org/archives/2026/08/ninth-circuit-lifts-restrictions-on-agentic-ai-accessing-amazon.htm); [Cooley](https://www.cooley.com/news/insight/2026/2026-08-06-ninth-circuit-rules-on-ai-agent-access-to-third-party-websites-under-cfaa); [PYMNTS](https://pymnts.com/news/artificial-intelligence/2026/ninth-circuit-narrows-cfaa-reach-in-perplexity-agentic-commerce-ruling); [eWeek](https://www.eweek.com/news/perplexity-ai-shopping-agent-returns-amazon/)
- Facebook v. Power Ventures (9th Cir. 2016): initial access with users' consent was not unauthorized, but after Facebook's cease-and-desist (plus IP blocking) "permission from the users alone was not sufficient"; a ToS violation "without more" cannot ground CFAA liability. [Justia: Facebook v. Vachani](https://law.justia.com/cases/federal/appellate-courts/ca9/13-17102/13-17102-2016-12-09.html); [Fenwick](https://www.fenwick.com/publications/Pages/Accessing-a-Website-After-Receiving-a-Cease-and-Desist-Letter-Is-a-Violation-of-the-CFAA.aspx); [Apify blog](https://blog.apify.com/facebook-v-power-ventures/)
- Van Buren and hiQ: commentators read Van Buren plus hiQ (9th Cir. 2022) as largely ending CFAA claims based on ToS violations alone, with "without authorization" for login-walled areas still the riskier zone; hiQ ultimately lost on breach of contract (LinkedIn user agreement prohibited scraping and fake accounts). [Fenwick: hiQ scrapes by again](https://fenwick.com/insights/publications/hiq-labs-scrapes-by-again-the-ninth-circuit-reaffirms-that-data-scraping-does-not-violate-the-cfaa-1); [White & Case](https://www.whitecase.com/publications/article/web-scraping-website-terms-and-cfaa-hiqs-preliminary-injunction-affirmed-again); [NatLawReview](https://natlawreview.com/article/hiq-labs-v-linkedin)
- DMCA 1201: Copyright Office exemptions can only cover the act of circumvention under 1201(a)(1), not trafficking in tools under 1201(a)(2)/(b); the 1201(j) security-testing exemption requires authorization; no exemption was found for bypassing pinning to reach your own app data. [Rapid7 on 1201](https://www.rapid7.com/blog/post/2021/11/15/thawing-out-the-chilling-effect-of-dmca-section-1201/); [Software Freedom Conservancy: DMCA exemptions explained](https://sfconservancy.org/blog/2020/dec/16/dmca-exemptions-explained/); [CRS RL33887](https://www.everycrsreport.com/reports/RL33887.html)
- App ToS specifics: Cronometer terms (Feb 12, 2025) bar scraping/automated scripts to collect Content for AI training (s.10(b)), terminate the license on attempts to "circumvent any technical protection measures" (s.4(f)), bar sharing login info except with Pro users (s.1(a)), and say third-party services are used "at your own risk" (s.7(a)). MyFitnessPal grants a "limited, revocable, personal, non-transferable, and non-exclusive" license for personal noncommercial use and its ToS FAQ asks users not to scrape. Strava's API terms ban AI use of API data. [Cronometer Terms](https://cronometer.com/terms); [MyFitnessPal Terms](https://www.myfitnesspal.com/terms-of-service); [DC Rainmaker on Strava](https://dcrainmaker.com/2024/11/stravas-changes-to-kill-off-apps.html)
- Canvas institutions treat student tokens as a security issue (MFA bypass) and are disabling them; automating against a school's instance also implicates the school's acceptable-use policy. [UM System](https://tdx.umsystem.edu/TDClient/66/MOOnline/KB/ArticleDet?ID=2302)

### Inferences
- Architecture is now a legal variable: a design where the user's own device (or a browser the user controls) makes the requests, and the vendor only plans/instructs, tracks the Perplexity facts. A hosted MCP server that stores the user's MFP cookie and calls MFP from the vendor's datacenter looks more like Power Ventures (vendor's systems contacting the platform directly) and loses the "tool, not person" shield, especially after any cease-and-desist.
- Realistic consequence for a user automating their own account is account suspension under ToS, not prosecution; for a vendor at scale it is breach-of-contract/tortious-interference suits and C&Ds that convert future access into CFAA exposure.
- Bypassing cert pinning or attestation to discover endpoints: unsettled whether pinning is a 1201 "technological measure that effectively controls access to a work"; distributing a bypass tool is the riskier act. Cronometer's ToS explicitly treats TPM circumvention as license-terminating. A product should do discovery on unpinned surfaces (web apps) or rely on public community work, and never ship bypass tooling to users (inference, not legal advice).
- The Ninth Circuit ruling binds only the Ninth Circuit, is preliminary, and could be reheard or reviewed; treat it as favorable but not settled as of Nov 2026.
- Academic integrity is a separate non-legal risk for Canvas writes (submitting work, posting discussions via agent).

### Gaps
- No case found that squarely addresses a user scraping their own logged-in account data with a self-run tool.
- No source found on any of the nine target apps actually banning accounts for API/automation use (anecdotes not located).
- Exact text of MyFitnessPal's automated-access clause not retrieved (page truncated).
- Status of any Amazon rehearing petition after Aug 2026 not found.

- Ordering the routes for a general "engineer its own API" system: (1) official API/OAuth if available and AI use permitted; (2) existing community MCP if maintained (check release recency; e.g., cronometer-api-mcp shipped 20 releases in 6 months, which signals both active upkeep and frequent breakage); (3) one-time HAR capture on the web app compiled into a client (Integuru / reverse-api-engineer / Unbrowse pattern) with on-failure re-capture; (4) browser agent on the web app as runtime fallback; (5) native UI automation (Android) or App Intents/Shortcuts (iOS); (6) export ingest for history.
- From a phone alone, a consumer product can deliver: official-API apps (Hevy, Canvas), web-backed apps via an in-app embedded browser that captures the session and runs calls from the device, HealthKit/Health Connect data, and Shortcuts-exposed actions. Mobile-only apps without App Intents (Strong, Fitbod) need a one-time desktop/cloud discovery step or Android UI automation.

### Gaps

- Did not confirm whether Strong or Fitbod have any web app login surface beyond marketing sites.
- Did not test whether Hevy write endpoints accept arbitrary historical workouts at scale beyond the Fitbod importer's 1.5 s pacing.
